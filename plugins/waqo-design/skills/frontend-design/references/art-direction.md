# Art Direction, Divergence, and Spatial Composition

Use this reference during concept exploration and before token definition.

## Generate real alternatives

For substantial new work, create at least three art directions.

Different directions must represent different mental models.

Not sufficient:
- light;
- dark;
- blue.

Sufficient:
- geographic operations canvas;
- editorial project atlas;
- dense command ledger.

If two concepts can become one another through token changes, they are not truly different.

For each direction define:

```yaml
name:
thesis:
product_rationale:
composition:
information_model:
typographic_behavior:
material_or_imagery:
interaction_model:
signature_move:
controlled_violation:
risk:
```

Push each direction far enough that choosing between them matters.

Do not merge them into a safe compromise before selection.

## Select before tokenizing

Choose using:
- product fit;
- user needs;
- brand fit;
- originality;
- interaction clarity;
- technical feasibility.

Then define:

```yaml
art_direction:
  thesis:
  source_worlds:
  visual_behavior:
  quiet_elements:
  signature_move:
```

Tokens come afterward.

## Signature move

Every expressive concept should have one screenshot-worthy move.

Ask:
`What would a designer remember after five seconds?`

The move may be:
- spatial;
- typographic;
- visual;
- interactive;
- data-driven.

Examples:
- map becomes the application canvas;
- timeline doubles as navigation;
- selecting a project reorganizes surrounding information;
- a live curve becomes a structural axis;
- a system is navigated as a schematic.

Define:

```yaml
signature_move:
  description:
  product_reason:
  user_value:
  interaction:
  visual_consequence:
```

If it works unchanged in an unrelated app, it is not specific enough.

## Controlled violation

Consider deliberately breaking one normal application convention when it strengthens the concept:
- oversized type crossing regions;
- asymmetric navigation;
- intentional off-canvas cropping;
- nonuniform columns;
- extreme scale contrast;
- overlap;
- floating controls;
- unusually dense local regions;
- image or data visualization as dominant plane.

The violation must preserve:
- comprehension;
- core actions;
- responsiveness;
- accessibility.

## Compose before components

Do not start by imagining:

```text
section
  container
    grid
      card
      card
```

Think in spatial terms:
- dominant region;
- support region;
- axis;
- anchor;
- edge;
- cluster;
- flow;
- interruption;
- negative space;
- density;
- depth.

Sketch spatially first. Derive components second.

## Card test

Visible containment is justified when content is:
- independently selectable;
- meaningfully grouped;
- repeated;
- movable;
- genuinely separated from surrounding context.

A DOM wrapper does not require a visible rounded rectangle.

## Characteristic state

Identify the state that best communicates what the product actually does:
- live;
- selected;
- editing;
- comparing;
- warning;
- historical;
- AI-suggested;
- empty;
- loading;
- failure;
- success.

Design that state, not only a polished idle view.
