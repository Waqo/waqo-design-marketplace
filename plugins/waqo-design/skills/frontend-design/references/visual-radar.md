# Visual Radar and Reference Decomposition

Use this reference when creating a new visual direction, materially redesigning a surface, or when the user asks for contemporary, expressive, portfolio-grade, Dribbble/Awwwards-level, or non-generic UI.

## Build three reference pools

When web/image research is available, gather a small, useful set rather than a huge moodboard.

### 1. Domain references
Look at:
- products serving similar users;
- category leaders and adjacent products;
- interfaces solving the same interaction or information problem;
- the actual physical or professional environment behind the software.

Search using domain nouns and interaction problems, not only aesthetic adjectives.

Weak query:
`modern dashboard UI`

Stronger queries:
`solar field operations interface`
`energy monitoring map UI`
`commercial project scheduling interface`
`utility control room visualization`

### 2. Contemporary craft references
Prefer recent work from:
- strong design showcases;
- product launches;
- reputable studios;
- designer portfolios;
- current design communities;
- contemporary product interfaces.

Use current references to understand the visual field, not to discover a template.

### 3. Cross-domain references
Borrow visual logic from outside software when useful:
- architecture;
- editorial design;
- exhibition systems;
- maps and wayfinding;
- automotive instrumentation;
- industrial control systems;
- sports broadcast graphics;
- scientific visualization;
- fashion;
- packaging;
- film titles;
- games;
- physical tools.

Cross-domain references are often where product-specific ideas emerge.

## Trend radar

Classify observed patterns:

### Current and useful
Contemporary techniques that still have conceptual room.

### Emerging
Newer forms worth understanding but not automatically using.

### Overexposed
Patterns that now function as defaults.

### Category-specific
Patterns common because they solve a real problem in the domain.

### Irrelevant
Fashionable techniques with no relationship to the brief.

Never turn a calendar year into a style recipe.

## Extract visual genes

Do not copy a full reference. Decompose it.

For each useful reference inspect:

### Composition
- dominant mass;
- grid;
- asymmetry/symmetry;
- negative space;
- overlap;
- crop behavior;
- reading path;
- edge behavior;
- vertical rhythm.

### Typography
- classification;
- width;
- weights;
- scale contrast;
- numeric treatment;
- display behavior;
- relation to imagery.

### Geometry
- rectangular/circular/radial/freeform/diagrammatic;
- repeated shapes;
- corner logic;
- borders;
- whether geometry encodes meaning.

### Surfaces and depth
- flatness;
- layering;
- shadows;
- transparency;
- blur;
- material simulation;
- elevation logic.

### Media
- photography;
- illustration;
- generated imagery;
- 3D;
- video;
- image-as-interface;
- full-bleed vs inset behavior.

### Density
- sparse;
- dense;
- regionally dense;
- progressive;
- overview vs detail.

### Interaction
- direct manipulation;
- navigation model;
- state transitions;
- spatial transitions;
- scroll behavior;
- feedback.

### Signature move
Name the single move that makes the reference memorable.

A reference may contribute one useful gene and nothing else.

## Synthesis rule

Never inherit the entire visual language of one reference.

Combine genes from multiple sources and transform them through:
- the product's subject matter;
- real user tasks;
- content shape;
- brand;
- technical constraints.

The final result should not be traceable to one source.
