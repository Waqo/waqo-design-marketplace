# waqo-design

A design-practice plugin for creating and evaluating contemporary digital products without collapsing into generic vibe-coded UI.

## Philosophy

**Discover a visual idea that could only belong to this product, then make it usable.**

This plugin separates creative generation from specialist review. The frontend-design skill owns art direction and implementation; companion skills own critique, design systems, UX writing, accessibility, research synthesis, and developer handoff.

## Skills

| Skill | Purpose |
|---|---|
| `frontend-design` | Contemporary visual research, divergent art direction, spatial composition, signature interactions, implementation, and visual iteration |
| `design-critique` | Evaluate usability, hierarchy, product specificity, visual craft, interaction, and genericness |
| `design-system` | Audit, document, extend, or evolve tokens, components, patterns, and expressive primitives |
| `ux-writing` | Create clear, consistent, product-appropriate interface copy |
| `accessibility-review` | Audit UI and implementation for accessibility and remediation |
| `research-synthesis` | Turn interviews, tests, surveys, feedback, and behavioral evidence into actionable design findings |
| `design-handoff` | Produce implementation-ready specs covering layout, states, responsive behavior, motion, tokens, edge cases, and accessibility |

## Typical greenfield workflow

1. Research the product and current visual field.
2. Generate at least three incompatible art directions.
3. Select a direction and define its signature move.
4. Compose spatially before deriving components.
5. Prototype a characteristic state with realistic content.
6. Render and critique.
7. Recompose structural weaknesses.
8. Productize responsive behavior, states, accessibility, and performance.
9. Formalize reusable patterns into the design system.
10. Produce handoff when design and implementation ownership differ.

## Existing-product workflow

1. Inspect the existing system before inventing new patterns.
2. Critique the target surface.
3. Identify whether the problem is UX, hierarchy, visual identity, system inconsistency, copy, accessibility, or implementation.
4. Use the relevant specialist skill.
5. Preserve intentional existing patterns unless the redesign explicitly supersedes them.

## Figma

A Figma MCP connection is included. The skills do not require it; screenshots, source code, or written design descriptions are also valid inputs.
